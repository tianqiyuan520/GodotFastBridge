# GodotFastBridge 设计分析

> 版本：2026 初稿（设计冻结）
> 定位：**C# → Godot 原生**的大数据提交互操作层（GDExtension + C ABI + C# facade）
> 依据：本机 Godot 引擎源码 `D:\Godot\GODOT\Source\godot-master`（4.5.0-beta 快照）、GodotSharp 4.4.1.0 / 4.7.0.0 程序集反射、本地项目代码（gdex / CSBS / 僵尸大战僵尸 / TerritorialWar / gameoflifedemo / gpu_pathing）
> 相关：`docs/Godot-C#互操作机制.md`（机制证据链）、`docs/收益模型与实测.md`（收益与实测）

## 一、一句话定位

把 **C# 向引擎提交大数据**这条路径，从

> 每次调用「引擎胶水新建临时容器 + 整块 memcpy + 释放」，且调用方常被迫先建托管大数组

降为

> **复用 grow-only 原生缓冲 + 直接吃调用方指针**；并把**回读**从「每次新建托管数组」改成「写进调用方缓冲」。

工程定位：**把已在本地被手写 3 遍的桥产品化**，不是新框架。

| 已有手写桥 | 位置 | 导出符号 |
|---|---|---|
| gdex 原型 | `gdex/src/gdexample.cpp:277/289/296`、`gdex/src/rd_submit_bridge.cpp:12` | 4 |
| CPUBattle 生产桥 | `ComputeShaderBattleSimulation/CPUBattle/GDExtension/src/cpubattle_bridge.cpp:13/21/28` | 3 |
| GDJobSystem C 导出层 | `GDJobSystem/src/gd_job_system_exports.cpp` | 14 |

## 二、要解决的问题

| 编号 | 问题 | 证据 | GFB 手段 |
|---|---|---|---|
| **P1** | 每次数组参数调用，引擎胶水 `resize` + `memcpy` + 释放 | `Generated/NativeCalls.cs:10048`、`Core/NativeInterop/Marshaling.cs:524-530`、`modules/mono/glue/runtime_interop.cpp:429-437` | 复用 grow-only 原生缓冲，消灭每次调用的分配/释放 |
| **P2** | 调用方被迫先建托管大数组再拷（僵尸每帧 2×1.44MB 进 LOH） | `僵尸…/RenderingManager.cs:354/:400-401` | ABI 直接吃源指针（支持 stride 提取） |
| **P3** | 回读每次新建托管数组 | `Marshaling.cs:450-461`；`gameoflifedemo/Main.cs:242`、`gpu_pathing/PBFS_Pathing/PBFS.cs:141` | `read_into(source, dst, offset, bytes)` |
| **P4** | 同一轮子手写 3 遍、各自带坑、各自重建 DLL | 三处桥 + CSBS 文档「改完必须重建 dll」 | 统一 ABI / 统一验证 / 统一版本矩阵 |
| **P5** | 提交开销不可诊断 | 各桥自写 `Time::get_ticks_usec` 计时 | C 内嵌 `fill_usec` / `submit_usec` + 累计统计 |

## 三、不做什么（硬边界）

| 不做 | 依据 |
|---|---|
| 不提供 PackedArray / 容器类型（含 `NativeArray`） | 零拷贝视图已由 `Span<T>` 承担；引擎容器不接受外部内存（`core/templates/cowdata.h` 无 wrap/proxy）；容器已有 `EntJoy.Collections` |
| 不承诺「零拷贝」 | 桥必须填 `PackedXArray`（`godot-cpp/.../rendering_device.hpp:717,758`、`rendering_server.hpp:901`）；4.5 RD 无 `buffer_map`（`servers/rendering/rendering_device.h:209,1706`） |
| 不做 StringName / NodePath / 集合 / EmitSignal / Call-Get-Set 优化 | 属「用错 API」，改 C# 代码即可，上桥反而多一次跳转（`runtime_interop.cpp:583`） |
| 不做批量物理读写（v1） | `PhysicsServer2D/3D` 在中转拷贝面里 0 处；属新原语，等第二个真实用例再进 v2 |
| 不做 GPU 侧（compute / indirect / 剔除） | 与互操作层无关 |
| 不接管渲染架构 | GFB 只做「数据怎么过去」，不做「画什么」 |

## 四、准入门槛（写进 README，不满足一律不接）

```
接入条件（全部满足）：
    单次 payload ≥ 256KB   或   同一帧跨界次数 ≥ 1000
    且 数据在 C# 侧已是连续内存

预期收益 = payload / (11~22 GB/s)          ← 一次可省掉的整块拷贝
         + 一次原生 alloc / free
         + 出向：一次托管分配 + 一次 MemoryCopy
```

## 五、架构

```
┌──────────────────────────────────────────────────────────────┐
│ C# 逻辑层                                                     │
│  数据源：EntJoy NativeArray<T> / pinned T[] / stackalloc       │
│  调用：FastBridge.Submit(slot, void* src, bytes)              │
└───────────────┬──────────────────────────────┬───────────────┘
                │ 配置面（低频，RID 安全）       │ 热路径（每帧，无 Variant）
                │ Call("configure_*", rid, n)   │ delegate* unmanaged[Cdecl]
                ▼                              ▼
┌──────────────────────────────────────────────────────────────┐
│ GDExtension DLL（同一模块实例）                               │
│  FastBridge(Node)  ── 槽位配置、持有 RID、持有 grow-only 缓冲  │
│  gfb_exports.cpp   ── C ABI 热路径（submit / read_into）       │
│  gfb_abi.h         ── ABI 版本 + GfbTiming（C# 侧镜像）        │
└───────────────┬──────────────────────────────────────────────┘
                │ godot-cpp（PackedXArray 参数不可避免）
                ▼
   RenderingDevice.texture_update / buffer_update
   RenderingServer.multimesh_set_buffer
   Image.set_data
```

**分层理由（两条都是被迫的，各有证据）**

1. **配置走 bound method**：`godot::RID` 是 8 字节 opaque、无 uint64 构造（`godot-cpp/gen/include/godot_cpp/variant/rid.hpp`），RID 只能经 Variant 传；配置本身低频。已在 `cpubattle_bridge.cpp:218` 验证可行。
2. **热路径走函数指针**：`get_*_address()` + `delegate* unmanaged[Cdecl]` —— 零 Variant、无委托分配、AOT 友好（GDJobSystem 已验证；现有桥的 `Marshal.GetDelegateForFunctionPointer` 应替换）。
3. **RID 值传递（仅 v2 批量原语用）**：C# `Rid.Id` 是 public 属性（反射已验证）；引擎 `RID::get_id()` 返回 `_id`（`core/templates/rid.h:70`）；godot-cpp `RID::_native_ptr()` 是 public → 可用 8 字节 memcpy 往返。**首次使用必须做往返断言。**

## 六、API 规格

### 6.1 GDExtension 类 `FastBridge : Node`（配置面）

```cpp
// 槽位类型化配置（一次性）
void configure_texture(int slot, const RID &texture, int byte_capacity);
void configure_storage_buffer(int slot, const RID &buffer, int byte_capacity);
void configure_multimesh(int slot, const RID &multimesh, int instance_count, int floats_per_instance);
void configure_output(int slot, int source_kind, const RID &source, int byte_capacity);

// 生命周期
void clear_slot(int slot);
void set_slot_enabled(int slot, bool enabled);

// 热路径地址（C# 只取一次用于构造函数指针）
int64_t get_submit_address() const;
int64_t get_submit_strided_address() const;
int64_t get_read_address() const;
int64_t get_context_address() const;
int     get_abi_version() const;

// 观测
Dictionary get_stats() const;   // 每槽：调用次数 / 累计 fill / 累计 submit / 缓冲峰值
```

### 6.2 C ABI（`extern "C" GDE_EXPORT`，热路径，无 Godot 类型）

```c
typedef struct { double fill_usec; double submit_usec; } GfbTiming;

int   gfb_abi_version(void);                         // C# 启动校验
void  gfb_submit        (void *ctx, int slot, const void *src, int bytes, GfbTiming *out);
void  gfb_submit_strided(void *ctx, int slot, const void *src, int count,
                         int stride, int elem_bytes, GfbTiming *out);
int   gfb_read_into     (void *ctx, int slot, void *dst, int offset, int bytes, GfbTiming *out);
// v2（依赖 RID 值传递，先做往返断言）
int   gfb_read_states_into(void *ctx, const uint64_t *rid_ids, int count,
                           int stride, int elem_bytes, void *dst, GfbTiming *out);
void  gfb_flush         (void *ctx);                 // 可选：帧末合并提交
```

### 6.3 C# facade

```csharp
public readonly struct GfbSlot { public readonly int Index; }

public static unsafe class FastBridge
{
    public static void Initialize(Node host);                  // 找 FastBridge 节点 + 取地址 + 校验 ABI
    public static GfbSlot ConfigureTexture(Rid rid, int bytes);
    public static GfbSlot ConfigureStorageBuffer(Rid rid, int bytes);
    public static GfbSlot ConfigureMultiMesh(Rid rid, int instances, int floatsPerInstance);
    public static GfbSlot ConfigureOutput(int sourceKind, Rid rid, int bytes);

    public static void Submit<T>(GfbSlot s, T* src, int bytes,
                                 out double fillMs, out double submitMs) where T : unmanaged;
    public static void SubmitStrided<T>(GfbSlot s, T* src, int count, int stride, int elemBytes,
                                        out double fillMs, out double submitMs) where T : unmanaged;
    public static int ReadInto(GfbSlot s, void* dst, int offset, int bytes);

    public static bool Enabled { get; set; }                   // A/B 开关（回退原生路径）
    public static GfbStats Stats { get; }
}
```

**GFB 不提供容器类型**：数据源用 `EntJoy NativeArray<T>.GetUnsafePtr()` / `fixed` / `stackalloc`，统一以 `void*` 进入。

### 6.4 数据契约（必须文档化）

1. **每槽一个 grow-only 缓冲**：`resize` 只发生在 `configure` 与超限扩容时（超限即扩容并记 stats）。
2. **同步消费**：C# 指针仅在调用期内有效，原生**不得保留**；Debug 下提供计数断言。
3. **stride 语义**：从每个元素起始地址取 `elem_bytes`；`stride == elem_bytes` 时等价于一次 `gfb_submit`。
4. **线程**：提交发生在引擎允许的线程；与 GDJobSystem 组合时采用「并行填充 → 主线程提交」。
5. **ABI 版本**：`gfb_abi_version()` 不匹配即抛错，不静默降级。
6. **回退**：`Enabled == false` 时 facade 走原生 API 路径（用于 A/B 与线上兜底）。

## 八、构建与版本矩阵

- **目标版本**：同时支持 **4.4.1** 与 **4.7**（机制在两者完全一致，无需条件编译）；`compatibility_minimum = "4.4"`。
- `SConstruct`：`libname = "GodotFastBridge"`，`CPPDEFINES=["GFB_EXPORTS"]`；C++17（无内核依赖，不需要 GDJobSystem 的 C++20）。
- 依赖：仅 godot-cpp；**零第三方依赖、零跨项目耦合**。
- 已知工程坑（GDJobSystem 已踩，同样适用）：
  - 编辑器开着时重编 DLL → 文件被锁；
  - 迁移 `.gdextension` 路径后需删 `project/.godot/` 重建缓存。

## 十四、实测后的定位修正（基于本轮 A/B，最终结论）

实测把立项时的预期砍掉了大半，必须落到定位上：

| 立项时的说法 | 实测结果 | 修正 |
|---|---|---|
| P1「每次调用都有临时容器分配/拷贝」→ 全部数组参数 API 受益 | 机制成立，但**只有三条提交通道有量级收益** | 收敛到 `buffer_update` / `texture_update` / `multimesh_set_buffer` |
| `Image.SetData` 属 P0 落点 | **写入方向 0.85~1.19×，无收益**（疑似 `Image::set_data` 直接接管传入容器，其 C# 路径本身只有一次拷贝） | 从落点清单移除；该槽位**仅用于回读**（2.00×） |
| 「每帧 N 次小跨界调用」可批量优化 | `PhysicsServer*` 不在中转拷贝族（0 处），且批量原语需另造 | 保留为 v2 设想，无本地用例前不做 |
| 「P0~P4 五类痛点全覆盖」 | 实际只覆盖**一类**（大 payload 提交）+ 回读的托管分配归零 | 原 Layer B（字符串/集合缓存）、Layer C（共享内存）**全部不立项** |
| 收益「+60%」 | 提交方向实测 **1.7~4.2×**（比预期更乐观），但换算成帧内占比只有 **~1.5%**（30k 实例）~ **~14%**（1M 单位） | 见下 |

**最终定位（一句话）**

> GFB 是给「**每帧向引擎搬运 ≥ 8 MB 数据**」的项目用的窄工具：在 1M 单位级场景值约 **14%** 帧时间，在 30k 实例级场景只值约 **1.5%**。
> 它**不是**通用性能优化库；小 payload 项目接入不划算。

**收益构成（实测口径）**

```
提交方向 = 省掉一次原生容器分配/释放 + （调用方本有中转时）一次整块拷贝
回读方向 = 省掉一次托管数组分配（1~4 MB/次）与一次 MemoryCopy —— 主要价值在 GC
```

**仍未量化的部分（本轮未测，不写进结论）**：托管分配归零的 GC 收益。僵尸式写法是每帧 2.88 MB 进 LOH，60fps 下 ≈173 MB/s 的 LOH churn；若该项可观，30k 级场景的结论可能上修。对应 M0 第②③项（原生 `resize`/`free` 孤立成本、LOH 时间占比）均未分离测量。
